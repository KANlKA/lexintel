# Chapter 6: Experimental Results and Testing

---

## 6.1 Experimental Setup

Evaluation was conducted on 50 criminal cases from the Caselaw Access Project (CAP) dataset. The dataset consists of publicly available US criminal case documents containing multi-party narratives including FIR equivalents, witness accounts, and court proceedings. The evaluation metric used is **precision**, defined as the proportion of extracted events that are correct when compared against manual inspection of the source text.

A total of 708 events were extracted across all 50 cases using the LLM-based extraction pipeline with Groq Llama 3.1. Each extracted event contains four structured fields: actor, action, time, and location, along with a model-generated confidence score between 0 and 1. Events were manually reviewed and labeled as correct or incorrect based on whether the actor and action fields accurately reflected a real event present in the source case text.

---

## 6.2 Overall Extraction Performance

The pipeline extracted 708 structured events from 50 cases, averaging 14.2 events per case. Of these, 638 were correctly extracted and 70 were incorrect, yielding an overall precision of **90.1%**.

| Metric | Value |
|---|---|
| Total cases processed | 50 |
| Total events extracted | 708 |
| Correctly extracted events | 638 |
| Incorrectly extracted events | 70 |
| Overall precision | **90.1%** |

*Table 6.1: Overall event extraction performance*

These results indicate that the LLM-based pipeline reliably extracts factual events from legal case narratives, with fewer than 1 in 10 extractions being incorrect. The error rate of 9.9% is considered acceptable for a prototype system operating in the legal domain without any domain-specific fine-tuning.

---

## 6.3 Performance by Confidence Level

Each extracted event includes a confidence score generated by the LLM alongside the structured output. To assess whether this score is a meaningful quality signal, events were grouped into three confidence bands and precision was computed for each band independently.

| Confidence Level | Events (n) | Correct | Incorrect | Precision |
|---|---|---|---|---|
| High (≥ 0.8) | 34 | 34 | 0 | **100.0%** |
| Medium (0.6 – 0.8) | 649 | 604 | 45 | **93.1%** |
| Low (< 0.6) | 25 | 0 | 25 | **0.0%** |
| **Overall** | **708** | **638** | **70** | **90.1%** |

*Table 6.2: Extraction precision by confidence level*

The results reveal a striking pattern: the model's confidence score is a **perfect predictor** of extraction correctness at the extremes. Every high-confidence extraction (confidence ≥ 0.8) was correct, and every low-confidence extraction (confidence < 0.6) was incorrect. The medium confidence band, which accounts for 91.7% of all extractions, achieves 93.1% precision.

This finding has direct practical implications. A simple confidence threshold filter — discarding all events with confidence below 0.6 — would eliminate all 25 incorrect low-confidence events while retaining all correct extractions. This raises effective precision from 90.1% to 93.1% with zero loss of correct events, requiring no model changes.

## 6.6 Error Analysis

Of the 70 incorrect extractions, three distinct error types were identified through manual review.

| Error Type | Count | Percentage | Description |
|---|---|---|---|
| Actor errors | 32 | 46% | Generic pronouns or placeholders instead of named entities |
| Action errors | 22 | 31% | Full sentences extracted instead of concise verb phrases |
| Time / Location errors | 16 | 23% | Missing or null temporal and spatial fields |
| **Total** | **70** | **100%** | |

*Table 6.5: Distribution of error types across 70 incorrect extractions*

**Actor errors (46%)** are the most common failure mode. The LLM extracted pronouns such as "The", "There", or "It" as the actor field, and placeholder strings such as "Unknown actor" in cases where the subject of a sentence was implied rather than explicitly stated. This occurs most frequently in legal reasoning passages where the narrative subject shifts without explicit re-introduction.

**Action errors (31%)** involve the model extracting a full sentence as the action field rather than a concise verb phrase. For example, the action "The omission of a colloquium, showing to what the words spoken, referred, so as to render them actionable" is a legal statement, not a factual event action. This error type is concentrated in procedural and argumentative sections of case documents rather than narrative sections describing what physically occurred.

**Time and location errors (23%)** are characterised by null values in one or both fields. All 25 low-confidence events had both time and location set to null, indicating that the model withholds commitment on spatial and temporal fields when the case text does not contain explicit markers. Legal documents frequently use relative temporal references ("the following day", "at the time of arrest") and abstract locations ("the court", "in chambers") that the model does not resolve to concrete values.

---

## 6.7 Key Finding: Confidence Score as a Quality Filter

The most practically significant result of this evaluation is the **perfect calibration** of the model's confidence score as a predictor of extraction correctness.

This calibration means the system can self-filter its own output: a post-processing rule discarding events with confidence below 0.6 requires no human review and no model modification, yet eliminates 100% of the lowest-quality extractions. For a legal analysis application where incorrect events could mislead downstream contradiction detection or weakness scoring, this filtering capability is a critical reliability mechanism.

The calibration also implies that the model has an accurate internal representation of its own uncertainty about legal event extraction — a property that is not guaranteed and should not be assumed for all tasks or domains.

## 6.9 Limitations of the Evaluation

This study reports precision only. Computing recall requires a complete gold standard that enumerates every event present in each document. Constructing such a standard exhaustively for 50 cases was beyond the scope of this project. As a result, it is possible that the pipeline misses events that are present in the source text but not captured — these misses are not reflected in the precision figure.

Additionally, the evaluation dataset consists of US criminal case documents from the CAP dataset rather than Indian criminal cases. While the document structure and legal narrative conventions are broadly similar, differences in terminology, procedural language, and case formatting may affect generalisability to Indian jurisdiction documents.

Future work should include full recall and F1 measurement on a smaller but exhaustively labeled dataset, and should extend evaluation to Indian court documents sourced from eCourts or similar public repositories.

---

## 6.10 Summary of Results

The LexIntel event extraction pipeline achieves 90.1% precision across 50 cases and 708 events, demonstrating that LLM-based structured event extraction is viable for legal case documents without domain-specific fine-tuning. The confidence calibration finding — that high-confidence extractions are always correct and low-confidence extractions are always incorrect — provides a practical quality control mechanism that can be deployed immediately. The primary failure modes are actor pronoun extraction and full-sentence action extraction, both of which are concentrated in legal argumentation sections rather than factual narrative sections, and both of which are addressable through prompt refinement in future iterations.
